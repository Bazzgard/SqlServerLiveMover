USER GUIDE

SQL Server Live Moverの使い方

接続設定から移行結果の確認まで、安全に進めるための手順をまとめています。

基本の流れ 設定 → 事前検査 → コピー／差分更新 → 件数検証

目次

実行前の確認 1. 接続と実行設定 2. 対象テーブル 3. 処理方式 4. 実行と検証 5. バックアップと復元 6. 設定ファイル よくある確認事項

BEFORE YOU START

実行前の確認

このツールは、作成済みのSQL Serverテーブル間でデータを移行します。テーブル定義そのものを作成するツールではありません。

  • 移行元・移行先のテーブルが作成済みである
  • 差分更新するテーブルには主キーがある
  • 移行元と移行先で主キーの列名と順序が一致している
  • 列を限定する場合も、主キー列をすべて含めている
  • 移行先の更新・バックアップ作成に必要な権限がある
移行元には書き込みません

事前検査とコピーは、移行元に対してSELECTだけを実行します。Change Trackingやトリガーの追加、データベース設定の変更も行いません。

STEP 1

接続と実行設定

メイン画面右上の「接続と実行設定」を開き、移行元と移行先の接続文字列を入力します。

接続文字列の例

Server=localhost,1433;Database=DLSDB;User ID=your_user;Password=your_password;Encrypt=True;TrustServerCertificate=True
ServerとDatabaseを入れ替えないでください

Serverにはサーバー名とポート、Databaseにはデータベース名を指定します。

読み取り整合性

方式特長注意点
Snapshot
推奨		対象テーブルを同じ時点で読み取り、書き込みを妨げません。移行元でALLOW_SNAPSHOT_ISOLATION ONが必要です。ツールからは変更しません。
LockedDB設定を変更せず、読み取り中の整合性を保ちます。コピー中、移行元への更新や追加がロック待ちになる場合があります。
Read committed移行元への影響を抑えます。複数テーブルが完全に同じ時点の状態になる保証はありません。

そのほかの設定

バッチ行数
一度に転送する行数です。既定値は5,000です。
タイムアウト
SQL処理の待機上限です。既定値は120秒です。
キャンセル
設定変更を反映せず画面を閉じます。
読込
保存済みJSONを読み込みます。前回使用したファイルが初期表示されます。
保存
JSONへ保存し、内容をメイン画面へ反映します。

STEP 2

対象テーブルを設定

「＋ 追加」で行を増やし、移行するテーブルを指定します。「－ 削除」は選択中の行を一覧から外します。

項目入力内容例
移行元読み取るスキーマ名とテーブル名dbo.Customers
移行先書き込むテーブル。空欄なら移行元と同じ名前dbo.Customers
列（カンマ区切り）移行対象の列。空欄ならコピー可能な全列Id, Name, UpdatedAt
処理方式テーブルごとのコピー方法差分更新（削除なし）
列を限定するとき

差分更新では主キーが必要です。列を限定する場合も主キー列をすべて含めてください。

STEP 3

処理方式を選択

削除なし

差分更新（削除なし）

主キーで比較し、新しい行を追加、値が違う行を更新します。移行先だけに存在する行は残します。

削除あり

差分更新（削除あり）

追加・更新に加え、移行元に存在しない移行先の行を削除します。事前バックアップは必須です。

初回向け

空テーブルのみ

移行先が空の場合だけ全件コピーします。1行でも存在する場合は停止するため、既存データを変更しません。

全件置換

全削除してコピー

移行先をトランザクション内で空にしてから全件コピーします。既存データは置き換わります。

差分更新も移行元からは全件読み取ります

Change Trackingを使わず、移行先の一時テーブルへ対象データを転送して比較します。一時テーブルは処理終了時に削除されます。

STEP 4

事前検査・コピー・件数検証

  1. 1

    事前検査

    接続、テーブル構造、主キー、列、整合性設定を確認します。エラーが出た場合はコピーへ進まず、ログの内容を修正してください。

  2. 2

    コピー／差分更新

    確認画面に対象と削除・バックアップの有無が表示されます。内容を確認して実行してください。

  3. 3

    件数検証

    移行元と移行先の行数を比較します。差分更新（削除なし）は移行先だけの行を残すため、件数が多くなることがあります。

途中で失敗した場合

各テーブルの変更はトランザクションで処理されます。失敗したテーブルは、そのテーブルのコピー開始前の状態へ戻ります。

BACKUP

バックアップと復元

画面下部の「事前バックアップ」を有効にすると、変更前の移行先データを同じデータベース内のバックアップテーブルへ保存します。移行先が空の場合は作成されません。

dbo.__SqlMoverBackup_Customers_20260802_073000_a1b2c3d4
  • バックアップはコピーが失敗しても残ります
  • 正常終了後も自動削除しません
  • 主キー、外部キー、インデックス、権限は複製しません
  • 管理情報は接続先ではなく、EXE配下のローカルJSONに保存します

バックアップ管理画面

復元
対象テーブルの既存行を削除し、選択したバックアップの行を挿入します。
復元前に事前バックアップ
現在の対象テーブルをpre-restoreとして保存してから復元します。
削除
選択したバックアップテーブルを完全に削除します。
復元・削除は移行先を変更します

外部キーにより削除できない場合は復元が失敗し、ロールバックされます。制約は自動的に無効化しません。

CONFIGURATION

設定ファイルと保存場所

設定画面の「保存」で、接続先・実行設定・対象テーブルをJSONへ保存できます。

{
  "sourceConnectionString": "${SQL_MOVER_SOURCE}",
  "targetConnectionString": "${SQL_MOVER_TARGET}",
  "batchSize": 5000,
  "commandTimeoutSeconds": 120,
  "sourceConsistency": "snapshot",
  "tables": [
    {
      "source": "dbo.Customers",
      "target": "dbo.Customers",
      "operationMode": "upsertKeep",
      "backupBeforeCopy": true
    }
  ]
}
ファイル用途
任意のmover.jsonユーザーが保存・読み込みする移行設定
logs\last-session.json前回の画面内容を自動復元
logs\backup-catalog.jsonバックアップ名、日時、件数、作成理由を管理
logs\last-config-path.txt前回使用した設定ファイルの場所を記録
接続文字列の保存

設定JSONと前回画面状態には接続文字列が保存されます。パスワードを残したくない場合は、${SQL_MOVER_SOURCE}のような環境変数参照を使用してください。

TROUBLESHOOTING

よくある確認事項

Snapshotが利用できないと表示されます

移行元でALLOW_SNAPSHOT_ISOLATIONが有効かDB管理者へ確認してください。設定を変更できない場合は、影響を理解したうえでLockedまたはRead committedを選択します。

差分更新が実行できません

移行元・移行先の主キー列名と順序を確認してください。列を限定している場合は主キー列がすべて含まれている必要があります。

事前バックアップを選んでも作成されません

移行先が空の場合はバックアップ対象となるデータがないため、自動的に省略されます。

前回使ったJSONが読込画面に出ません

初回は設定ファイルを選択して保存してください。次回から同じファイルを初期表示します。ファイルを移動・削除した場合は初期表示されません。

設定が完了したら、必ず「事前検査」から開始してください。
